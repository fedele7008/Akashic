# Akashic Reverse Proxy

Internal nginx reverse proxy that routes requests to Docker services based on subdomain matching. All services share a single port (default `8280`).

## Architecture

```
Internet
  |
  v
Host-level nginx (HTTPS termination)   <-- required for production
  |
  v
Akashic proxy (port 8280)              <-- this service
  |
  +-- vault.*      --> vault:8200       (Vault UI + API, HTTPS upstream, Vault's own auth)
  +-- adminer.*    --> adminer:8080     (database UI, basic auth + rate limited)
  +-- pki paths    --> vault:8281       (CRL/CA distribution, unauthenticated)
  +-- (default)    --> 403 Forbidden
```

## Prerequisites

### HTTPS Termination (Required for Basic Auth)

The Akashic proxy serves HTTP only. **Basic auth credentials are sent as Base64-encoded plaintext.** Without HTTPS in front, passwords are visible to anyone intercepting traffic.

**You MUST run a host-level reverse proxy with TLS termination** (nginx, Caddy, Traefik, etc.) in front of the Akashic proxy before exposing it to the network.

See [Host-Level Reverse Proxy Setup Guide](../host-nginx-setup.md) for full instructions, including TLS certificates, wildcard DNS, and nginx configuration.

### Wildcard DNS or /etc/hosts

Subdomain routing requires the `Host` header to match patterns like `adminer.<domain>`. This means:

- **With a domain:** Configure wildcard DNS (`*.akashic.example.com` -> your server IP)
- **Without a domain:** See [Access Without a Domain](#access-without-a-domain) below

## Services

### PKI: CRL and CA Certificate Distribution

| | |
|---|---|
| **Subdomain** | Any (default server block) |
| **Auth** | None (public, read-only) |
| **Rate limit** | None |

Exposes Vault PKI endpoints for certificate revocation lists and CA certificates:

```
GET /v1/{engine}/crl       Certificate Revocation List (DER)
GET /v1/{engine}/crl/pem   Certificate Revocation List (PEM)
GET /v1/{engine}/ca         CA Certificate (DER)
GET /v1/{engine}/ca/pem    CA Certificate (PEM)
```

All other paths return `403 Forbidden`.

Example:
```bash
curl http://localhost:8280/v1/pki-root/ca/pem
curl http://localhost:8280/v1/pki-internal/crl/pem
```

### Vault UI and API

| | |
|---|---|
| **Subdomain** | `vault.*` |
| **Auth** | Vault's own auth (token, userpass, OIDC, etc.) |
| **Rate limit** | None |

Proxies to the Vault HTTPS listener (port 8200). The proxy verifies Vault's TLS certificate against the bootstrap CA (`/certs/vault/root-ca.crt`).

All paths are forwarded: `/ui/` for the web interface, `/v1/` for API calls. Vault handles its own authentication -- no proxy-level auth is applied.

Example:
```
https://vault.akashic.example.com/ui/      # Vault web UI
https://vault.akashic.example.com/v1/sys/health  # API health check
```

### Adminer (Database UI)

| | |
|---|---|
| **Subdomain** | `adminer.*` |
| **Auth** | HTTP Basic Auth (optional, configured via env vars) |
| **Rate limit** | 5 req/s per IP, burst of 20 |

Web-based database management tool. Protected by rate limiting, and optionally by basic auth.

**Environment variables** (in `.env`):
```
AKASHIC_ADMINER_AUTH_USER=admin
AKASHIC_ADMINER_AUTH_PASSWORD=<your-password>
```

- **Both set:** Basic auth is enabled. The htpasswd file is generated at container startup using `openssl passwd -apr1` (no host-level `htpasswd` tool needed).
- **Either or both unset:** Basic auth is bypassed. Adminer is accessible without credentials.

**Rate limiting:** 5 requests per second per IP with a burst allowance of 20. Handles normal browsing (page loads, asset requests) without issues. Once exceeded, further requests receive `429 Too Many Requests`. The rate limit is applied before authentication, preventing brute-force attacks on the basic auth credentials.

## Configuration

### Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `AKASHIC_NGINX_PORT` | `8280` | Host port for the proxy |
| `AKASHIC_ADMINER_AUTH_USER` | (empty) | Basic auth username for adminer |
| `AKASHIC_ADMINER_AUTH_PASSWORD` | (empty) | Basic auth password for adminer |

### Changing Credentials at Runtime

Auth config is generated by the entrypoint on every container start. To apply changes:

```bash
# Edit .env, then:
docker compose up proxy -d          # detects env change, recreates container
```

**Note:** `docker compose restart proxy` does NOT re-read `.env` -- it reuses the existing container with old env vars. Always use `docker compose up -d` after changing `.env`.

### Adding a New Service

1. Add a `server` block to `services/proxy/nginx.conf` with `server_name ~^<subdomain>\.;`
2. Add auth/rate limiting as needed
3. If the service needs env vars, pass them through `docker-compose.yml` and generate config in `docker-entrypoint.sh`
4. Rebuild: `docker compose build proxy && docker compose up proxy -d`

## Access Without a Domain

Users without a domain name, wildcard DNS, or a host-level reverse proxy can still access services in two ways:

### Option 1: /etc/hosts (Recommended for local development)

Add entries to `/etc/hosts` to make subdomain routing work locally:

```
127.0.0.1  adminer.localhost
```

Then access `http://adminer.localhost:8280/` directly. The `Host` header will be `adminer.localhost` which matches `server_name ~^adminer\.;`.

**Note:** This only works on the local machine. Basic auth over plain HTTP is acceptable for localhost-only access since traffic never leaves the machine.

### Option 2: Direct port access (Bypass the proxy entirely)

Services also expose their own ports for direct access:

| Service | Direct URL | Notes |
|---------|-----------|-------|
| Vault UI | `https://localhost:8200/ui` | Vault's own TLS, requires root token |
| Adminer | `http://localhost:25000` | No basic auth, no rate limit (bound to 127.0.0.1 only) |

Direct port access bypasses the proxy entirely -- no basic auth, no rate limiting, no subdomain routing. Only use this for local development.

### Option 3: curl with Host header

For testing or scripting:

```bash
curl -u admin:password -H "Host: adminer.localhost" http://localhost:8280/
```

## Security Considerations

| Concern | Mitigation |
|---------|-----------|
| Basic auth over HTTP | HTTPS termination required upstream. Never expose port 8280 directly to the internet. |
| Brute-force attacks | Rate limiting: 5 req/s per IP + burst of 20 |
| Unauthorized access to PKI | Only CRL/CA endpoints exposed (read-only, public by design) |
| Adminer database access | Basic auth + rate limit. Adminer itself also requires DB credentials. |
| Direct port exposure | Adminer binds to `127.0.0.1` only (`127.0.0.1:25000:8080`). Not accessible from network. |

## Troubleshooting

**403 on adminer subdomain:**
- Verify the `Host` header reaches the proxy: `curl -H "Host: adminer.test" http://localhost:8280/`
- If using a host-level proxy, ensure `proxy_set_header Host $host;` is configured

**401 on adminer (credentials not working):**
- Check if env vars are set: `docker compose exec proxy env | grep ADMINER`
- Recreate the container (htpasswd is generated at startup): `docker compose up proxy -d --force-recreate`

**429 Too Many Requests:**
- Rate limit exceeded. Wait a few seconds or adjust `rate=5r/s` and `burst=20` in `nginx.conf`

**Connection refused on subdomain:**
- Ensure the target service is running: `docker compose ps`
- Check proxy logs: `docker compose logs proxy`
