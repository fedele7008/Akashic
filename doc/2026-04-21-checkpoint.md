## Certificate Hierarchy

```
Vault Bootstrap CA (vault/root-ca.crt)
│  └── vault.crt (Vault's own HTTPS — SEPARATE from Akashic PKI)
│
Akashic Root CA (ca/roots/root-ca.crt) — self-signed, 10yr, RSA 4096
├── Internal CA (ca/internal-ca.crt) — 5yr, RSA 4096
│   │
│   ├── Leaf certs (server TLS, 90-day TTL):
│   │   ├── akashic/ctrl.crt     — Control server
│   │   ├── akashic/auth.crt     — Auth server
│   │   ├── postgres/postgres.crt — PostgreSQL
│   │   ├── redis/redis.crt       — Redis
│   │   ├── ldap/ldap.crt         — LDAP
│   │   └── loki/loki.crt         — Loki
│   │
│   ├── akashic-ctrl mTLS CA (ca/mtls/akashic-ctrl/) — 5yr, RSA 2048
│   │   ├── akashic/mtls-ctrl.crt             — server identity
│   │   ├── akashic-cli/akashic-ctrl-client.crt — CLI client
│   │   └── bff/akashic-ctrl-client.crt        — BFF client
│   │
│   ├── ldap mTLS CA (ca/mtls/ldap/) — 5yr, RSA 2048
│   │   ├── ldap/mtls-ldap.crt                — server identity
│   │   ├── akashic/ldap-client.crt            — Akashic client
│   │   └── phpldapadmin/ldap-client.crt       — phpLDAPadmin client
│   │
│   └── loki mTLS CA (ca/mtls/loki/) — 5yr, RSA 2048
│       ├── loki/mtls-loki.crt                — server identity
│       ├── akashic/loki-client.crt            — Akashic client
│       └── grafana/loki-client.crt            — Grafana client
│
└── Public CA (ca/public-ca.crt) — 5yr, RSA 4096
    └── (browser-facing certs — issued when needed)
```

**Why two separate root CAs?**
- **Vault Bootstrap CA**: Only for Vault's own HTTPS listener. Generated by `vault-bootstrap` using OpenSSL before Vault even starts.
- **Akashic Root CA**: The PKI hierarchy for all Akashic services. Generated inside Vault using the PKI secrets engine.

## How Certificates Are Managed

### Initial Issuance (vault-init, 13 steps)

On first `docker compose up`, the pipeline runs automatically:

```
Step  1: Initialize Vault (Shamir 5/3, encrypted keys)
Step  2: Unseal Vault (SAT-based key discovery)
Step  3: Mount 6 PKI engines
Step  4: Generate Root CA (self-signed)
Step  5: Generate 5 Intermediate CSRs
Step  6: Sign Internal + Public CSRs with Root
Step  7: Register into engines (activates them as CAs)
Step  8: Sign 3 mTLS CSRs with Internal CA
Step  9: Register mTLS CAs
Step 10: Configure CRL/CA URLs on all engines
Step 11: Create 8 PKI roles (issuance policies)
Step 12: Issue 16 leaf certificates
Step 13: Create trust bundle (root + internal CA combined)
```

All steps are idempotent for Steps 1-3 (init, unseal, mount). Steps 4+ will fail on re-run with "already exists" — for a clean re-run, `docker compose down -v` resets Vault storage.

### Automatic Rotation (vault-agent)

After initial issuance, `vault-agent` takes over:

```
vault-agent (hashicorp/vault:1.20)
  │
  ├── Authenticates to Vault using decrypted root token
  ├── Uses pkiCert template function for each cert
  ├── Writes cert+key as a single .bundle file
  ├── split-bundle.sh splits into separate .crt + .key
  ├── Monitors cert TTL internally
  └── Re-issues at ~2/3 TTL (60 days for 90-day certs)
```

**Key design**: Each cert+key comes from a SINGLE `pkiCert` call (not separate calls) to ensure they always match. The bundle is split by a post-render script.

### How Services Pick Up New Certs

| Service | Mechanism | Downtime |
|---------|-----------|----------|
| **Akashic (Go)** | `CertReloader` polls file mod time every 30s, `GetCertificate` callback serves latest | **None** |
| **PostgreSQL** | cert-watcher sends `SIGHUP` → graceful TLS reload | **None** |
| **Redis** | cert-watcher sends `SIGTERM` → Docker restarts container | **Brief** (~2s) |
| **LDAP** | cert-watcher sends `SIGTERM` → Docker restarts | **Brief** |
| **Loki** | cert-watcher sends `SIGTERM` → Docker restarts | **Brief** |

The cert-watcher sidecars use `inotifywait` for instant detection + Docker socket to signal containers by name.

### CRL (Certificate Revocation)

Revoked certs are published via CRL endpoints:

```
Vault (:8281 HTTP, internal) → nginx proxy (:8280, public) → Client

http://<AKASHIC_PKI_CRL_BASE_URL>/v1/pki-root/crl      — Root CRL
http://<AKASHIC_PKI_CRL_BASE_URL>/v1/pki-internal/crl   — Internal CRL
```

The nginx proxy filters paths — only `/v1/*/crl` and `/v1/*/ca` pass through. All other Vault endpoints return 403.

## What Is Public vs Internal

### Public (accessible from outside Docker)

| Endpoint | Port | Purpose | TLS |
|----------|------|---------|-----|
| Auth server | 8080 | OAuth 2.1 / OIDC | Yes (Internal CA) |
| Nginx proxy | 8280 | Subdomain routing + CRL | No (HTTP) |
| PostgreSQL | 5432 | Database (for host tools) | Yes (Internal CA) |
| Redis | 6379 | Cache (for host tools) | Yes (Internal CA) |
| LDAP | 389/636 | Directory (embedded) | Yes on 636 |
| Loki | 3100 | Log aggregation | No (obs profile) |
| Grafana | 3000 | Dashboards | No (obs profile) |
| phpLDAPadmin | 8090 | LDAP admin UI | No (ldap profile) |
| Adminer | 25000 | Database UI | No |

### Internal Only (Docker network, not exposed to host)

| Endpoint | Port | Purpose |
|----------|------|---------|
| Vault HTTPS | 8200 | Authenticated API (localhost-only on host) |
| Vault HTTP | 8281 | CRL/CA distribution (only via nginx proxy) |
| Control server | 8081 | Admin API (localhost-only, mTLS required) |

### Subdomain Routing (via nginx proxy :8280)

Requires DNS wildcard `*.yourdomain` → external nginx → project proxy:

| Subdomain | Backend |
|-----------|---------|
| `pki.*` | vault:8281 (CRL/CA only, other paths → 403) |
| `vault.*` | vault:8200 (Vault UI) |
| `grafana.*` | grafana:3000 |
| `adminer.*` | adminer:8080 |
| `ldapadmin.*` | phpldapadmin:80 |
| anything else | 403 |

Domain-agnostic — only the subdomain prefix matters. Users without domains access services directly via their ports.

## Service TLS Configuration

### PostgreSQL

```yaml
# docker-compose.yml
command: >
  -c ssl=on
  -c ssl_cert_file=/var/lib/postgresql/certs/postgres.crt
  -c ssl_key_file=/var/lib/postgresql/certs/postgres.key
  -c ssl_ca_file=/var/lib/postgresql/certs/trust-bundle.pem
```

Uses a custom entrypoint that copies certs from the shared volume to a postgres-owned directory (PostgreSQL requires the key file to be owned by UID 70 with mode 0600).

### Redis

```yaml
command: >
  redis-server --tls-port 6379 --port 0
  --tls-cert-file /certs/redis/redis.crt
  --tls-key-file /certs/redis/redis.key
  --tls-ca-cert-file /certs/ca/trust/trust-bundle.pem
  --tls-auth-clients no
```

Redis listens on TLS-only (port 0 disables plain TCP). Health check uses `redis-cli --tls`.

### LDAP (osixia/openldap)

```yaml
environment:
  LDAP_TLS: "true"
  LDAP_TLS_CRT_FILENAME: "ldap.crt"
  LDAP_TLS_KEY_FILENAME: "ldap.key"
  LDAP_TLS_CA_CRT_FILENAME: "trust-bundle.pem"
entrypoint: # copies certs + chowns to openldap user before starting
```

Uses a custom entrypoint to copy certs from the read-only volume and fix ownership (osixia image requires certs owned by UID 911).

### Akashic Go Server

```yaml
# configs/config.yaml
server:
  auth:
    tls:
      enabled: true
      cert_file: "./certs/akashic/auth.crt"
      key_file: "./certs/akashic/auth.key"
  control:
    tls:
      enabled: true
      cert_file: "./certs/akashic/ctrl.crt"
      key_file: "./certs/akashic/ctrl.key"
      ca_file: "./certs/ca/mtls/akashic-ctrl/akashic-ctrl-ca.crt"
      client_auth_required: true
```

Uses `pkg/pki/CertReloader` for zero-downtime rotation. The reloader polls every 30 seconds and atomically swaps the in-memory cert when the file changes.

### Akashic → PostgreSQL

```yaml
database:
  postgres:
    ssl_mode: "verify-ca"
    ssl_root_cert: "./certs/ca/trust/trust-bundle.pem"
```

### Akashic → Redis

```yaml
database:
  redis:
    tls:
      enabled: true
      ca_file: "./certs/ca/trust/trust-bundle.pem"
```

### Akashic → LDAP

```yaml
ldap:
  port: 636
  use_tls: true
  tls_ca_file: "./certs/ca/trust/trust-bundle.pem"
```

## CLI Commands Created

All commands follow the pattern: `akashic-cli pki vault engine <subcommand>`

```
akashic-cli pki vault
├── status                              — Check vault health
├── init                                — Initialize with Shamir keys
├── unseal                              — SAT-based intelligent unseal
└── engine
    ├── mount <path>                    — Mount PKI engine
    ├── generate
    │   ├── root internal              — Generate self-signed root CA
    │   └── csr internal               — Generate intermediate CSR
    ├── sign intermediate              — Sign CSR with parent CA
    ├── register                       — Import signed cert into engine
    ├── config urls                    — Set CRL/CA distribution URLs
    ├── role create <name>             — Create issuance policy role
    └── issue                          — Issue leaf certificate
```

All commands support cascading config: `defaults → config file (-f) → inline JSON (--config) → dedicated flags (--cn)`.

## Security Notes

1. **`.secrets/` directory**: Contains encrypted vault root token and 5 unseal keys. Back up immediately. Loss = permanent vault lockout.
2. **`AKASHIC_SECRET`**: Currently `password123` (dev only). Must be 32+ chars for production. Used for PBKDF2 → HKDF → AES-256-GCM encryption.
3. **Private keys**: Written with `0600` permissions. PostgreSQL keys are copied into a postgres-owned directory for correct ownership.
4. **Vault HTTP listener (8281)**: Only accessible within Docker network. Exposed to host only through nginx proxy which filters to CRL/CA paths.
5. **mTLS blast radius**: Each service domain (ctrl, ldap, loki) has its own mTLS CA. Compromise of one doesn't affect others.
6. **Certificate lifetimes**:
   - Root CA: 10 years
   - Intermediate CAs: 5 years
   - mTLS CAs: 5 years
   - Leaf certificates: 90 days (auto-renewed at 60 days by vault-agent)

## How to Start from Scratch

```bash
# 1. Configure environment
cp .env.example .env
# Edit .env: set AKASHIC_SECRET to a strong 32+ char value

# 2. Start everything
docker compose --profile ldap --profile obs up -d --build

# 3. Watch initialization (13 steps)
docker compose logs -f vault-init

# 4. Verify
openssl verify -CAfile ./certs/ca/trust/trust-bundle.pem ./certs/akashic/ctrl.crt
curl -H "Host: pki.test" http://localhost:8280/v1/pki-root/ca/pem

# 5. Start Akashic server
go run ./cmd/akashic run --config configs/config.yaml --verbose

# 6. Bootstrap (first time only)
curl http://localhost:8081/bootstrap/status
curl -H "User-Agent: akashic-cli/1.0" http://localhost:8081/bootstrap/token
curl -X POST http://localhost:8081/bootstrap/root \
  -H "Content-Type: application/json" \
  -d '{"token":"<token>","username":"admin","email":"admin@akashic.local","password":"Admin123"}'
```

## Known Issues

1. **vault-init Steps 4+ not idempotent**: Re-running vault-init after initial setup fails with "issuer name already in use" / "role already exists". Steps 1-3 (init, unseal, mount) are idempotent. For a clean re-run: `docker compose down -v`.

2. **LDAP health check**: May show "unhealthy" during TLS initialization. The entrypoint copies certs and sets ownership before starting slapd — this adds startup delay.

3. **Vault Agent on first start**: If vault-init's Step 12 certs conflict with vault-agent's issuance, clear old leaf certs: `find ./certs -name "*.crt" -not -path "*/ca/*" -not -path "*/vault/*" -delete` then restart vault-agent.
